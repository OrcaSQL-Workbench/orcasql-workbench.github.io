# SQL 编辑与执行

适用版本：OrcaSQL Workbench 0.1.0。

## 选择执行目标

通过 **工具 → 查询编辑器** 打开工作区。执行前确认工具栏中的 **当前数据库连接** 和 **当前数据库**。

打开、编辑 SQL 文本与执行 SQL 是不同操作。不要仅凭文件名或标签页名称判断它将在哪个数据库中执行。

## 执行当前语句或选中内容

1. 在编辑器中输入 SQL，或使用 **打开 SQL 文件** 载入文本。
2. 核对所选连接和数据库，审阅 SQL 的操作范围及数据影响。
3. 使用 **执行当前语句或选中内容** 发起执行。
4. 在 **结果** 和 **消息** 中查看返回数据、执行状态和错误。

选中部分文本时，应确保所选内容就是你希望执行的 SQL。工作区正在处理查询、关闭、连接切换或事务操作时，需要先处理当前操作，不能把重复点击当作新的执行已开始。

## 停止与未知结果

使用 **停止查询** 发起取消请求。取消请求并不保证语句从未到达服务器，也不代表之前的修改已经回滚。

连接中断、强制断开或取消异常时，界面可能报告语句结果未知。此时不要直接重试可能修改数据的 SQL；先核对服务器中的实际结果和事务状态。

## 首选项

从 **编辑 → 首选项…** 打开设置。查询编辑器打开后，可调整 SQL 编辑和执行相关选项。

| 选项 | 作用 |
| --- | --- |
| 关键字大小写 | 关键字补全和格式化使用的大小写 |
| Tab 键 | 缩进 SQL 或将焦点移出编辑器 |
| 语句超时 | 仅在驱动支持正常取消时生效 |
| 最大行数 | 每个结果在截断前最多获取的行数 |
| 脚本错误 | 语句失败后停止或继续处理脚本 |
| 自动提交 | 所有查询标签页共用的设置 |

最大行数可选择 100、500、1,000、5,000、10,000 或 50,000。它限制结果加载范围，不是对修改语句影响行数的安全限制。

## 事务与自动提交

新连接默认开启自动提交。关闭自动提交后，应明确处理事务的提交或回滚。

自动提交设置由查询标签页共同使用。切换该设置、关闭查询或改变连接时，如果界面要求处理未完成事务，请先核对要保留还是撤销的修改。

结果查看不等于只读连接。应用会按所连接数据库账户的权限执行 SQL；需要数据库级只读权限时，应由数据库管理者配置账户权限。

文件保存与历史记录见 [SQL 历史与文件](History-and-Files.md)，返回数据的范围见 [结果查看与导出](Results-and-Export.md)。
