# SQL 历史与文件

## 查询历史

当前版本默认启用历史记录。默认保留限制为：

| 限制 | 默认值 |
| --- | --- |
| 历史保留时长 | 30 天 |
| 历史条目上限 | 500 条 |
| 历史存储上限 | 5 MiB |

在 **历史** 面板可以搜索 SQL、连接、数据库或执行结果，调整保留限制，并控制 **记录历史**。

超期或超限条目在载入、记录或调整设置时按存储流程处理；这不代表应用关闭后还有每日定时清理任务。

## 打开与再次执行

**在新查询中打开历史 SQL** 将文本放入新的查询，不应将“已打开”理解为“已执行”。

**执行历史 SQL** 会再次发起执行。历史中的 SQL 也可能修改或删除数据，执行前仍需核对连接、数据库及实际影响。

## 暂停与清空

关闭 **记录历史** 只停止后续记录，不会自动清空已有历史。

清空历史需要另行确认。它不会一并删除 SQL 草稿、导出文件、证书、私钥或数据库服务器中的业务数据。

如果界面报告历史只保留在内存中、无法保存到本地，不应认为历史已经可靠写入设备存储。

## SQL 文件

编辑器提供 **打开 SQL 文件**、**保存 SQL 文件** 和 **SQL 文件另存为**。

保存操作会把 SQL 文本写入所选文件位置。首次保存或另存为时，核对目标位置及文件名；保存失败时，以界面错误为准。

关闭有更改的查询时，如果应用询问是否保存，请按你的意图处理。不要把关闭标签页当作文件已经保存。

## 工作区恢复草稿

应用可以保存用于恢复编辑工作的 SQL 草稿。恢复草稿不等于你主动保存的 SQL 文件，也不等于完整备份。

恢复草稿没有统一的按天过期时间。保存、清理或恢复发生异常时，旧文件可能继续保留以避免数据丢失。

查询结果不会自动写入工作区恢复文件；如果需要保存数据，应主动导出结果。

## 避免保留敏感文本

SQL 草稿、执行历史和导出文件可能含有文本中的密码或业务数据。连接密码使用系统安全存储，不代表这些文本也受到相同保护。

相关范围见 [隐私政策](https://orcasql-workbench.github.io/privacy/)，导出操作见 [结果查看与导出](Results-and-Export.md)。
