# 故障排查与问题反馈

先记下实际使用的 HAR 版本、设备/API 和服务器类型，再对照下面的现象检查。这里的用法以 MySQL 1.0.2 为准。

## 安装后找不到 @arkdb/mysql

确认 HAR 已加入真正使用驱动的模块，而不是只放在工程目录。文件依赖路径相对于模块的 `oh-package.json5`，修改后要恢复依赖并重新构建。

只从 `@arkdb/mysql` 导入。不要注册 ArkDB 源码模块、导入包内路径或补一个 core override。还要核对当前 API-24 字节码包是否适合消费项目的工具链。步骤见[加入应用模块](Getting-Started.md#加入应用模块)。

## Worker 无法启动或消息不对

先检查 `build-profile.json5` 注册的入口与创建 Worker 时的路径是否对应。入口不要导出声明，共享 DTO 放在独立模块。

如果是消息转换问题，检查是否发送了连接、`QueryResult`、原始错误或 UI 对象，以及 `bigint` 是否被直接交给 JSON 序列化。不要靠跨线程传递连接来绕过消息设计。见 [Worker 集成](Worker-Integration.md)。

## 连不上服务器或认证失败

先用 `validateIssues()` 排除主机、端口、账号和配置错误；再核对最终应用的 INTERNET 权限、目标网络和服务器可达性。

认证错误要检查账号、授权和服务器认证设置。不要把原始密码或含用户名、SQL 的服务器消息贴进问题报告，也不要自动重试写入。错误类别见[错误与日志](Errors-and-Logging.md)。

## 证书校验失败

检查连接时使用的名称是否匹配证书，证书链是否被平台或选定 CA 信任，PEM 文件是否能被 HarmonyOS 应用进程读取。开发电脑上存在该文件，不代表应用沙箱内也能读取。

使用客户端证书时确认公钥证书和私钥成对配置。不要把 `VERIFY_IDENTITY` 改成明文或跳过验证作为自动回退。见[连接配置与 TLS](Connections.md)。

## 查询结果少了、精度不对或不能转 JSON

先检查 `truncated`、`truncationReason` 和结果预算。`maxRows: 0` 只表示不限行数，其他限制仍然生效。

BIGINT 是 `bigint`，DECIMAL 是字符串，SQL NULL 是 `null`。不要把精确值先转成 `number`，也不要直接序列化整个结果。见[数据类型与结果](Data-Types-and-Results.md)和[流式读取](Streaming.md)。

## 流式读取时连接关闭

检查 sink 是否长期不返回，以及是否一直累积行块。等待 sink 不会暂停套接字收包；接收队列和截断后的同步排空都有上限。

记录脱敏后的错误类别与所用预算，先缩小结果或处理每块所需的工作量，不要盲目扩大所有上限。排空失败后不能把连接当作已经恢复同步。见[处理截断](Streaming.md#处理截断)。

## 设置 statementTimeoutMs 后查询还在执行

这个字段只校验数值，不启动语句取消计时器。`Promise.race` 也只改变等待行为。应用要安排计时器、取消请求和原操作收尾，见[取消与超时](Cancellation-and-Timeouts.md)。

## 取消返回后能否立即复用连接

不能只看取消请求是否返回。先等待原操作结束，再看取消结果、连接生命周期和会话状态。

MySQL 已发出的控制命令如果超时或结果丢失，目标连接会永久停用。创建新实例，不要重开旧实例。原查询正常完成也可能只是赶在取消之前结束。见[取消结果与连接复用](Cancellation-and-Timeouts.md#取消结果与连接复用)。

## 服务器指标没有数据

检查 `availability` 和错误类别，不把 `data: null` 当成零。核对账号权限、服务器产品和所需的 Performance Schema 数据源。

Provider 使用的连接仍要与其他操作串行。见[元数据与服务器指标](Metadata-and-Metrics.md)。

## 断线或超时后能否重试写入

不要立即重连重试。响应丢失时，写入或提交可能已经发生；关闭连接、取消请求返回，甚至后续回滚成功都不能证明它没发生。

保留原始错误和清理错误，按应用自己的核对流程确认实际结果。若业务需要重试，应先具备相应的结果核对或幂等设计，而不是由驱动盲目重放。见[事务](Transactions.md)。

## 提交问题时附上什么

驱动问题请提交到 [ArkDB Issues](https://github.com/OrcaSQL-Workbench/ArkDB/issues)，附上：

- HAR 版本、下载的 Release，以及是否改过源码。
- DevEco/HarmonyOS API、设备类型，是否在真机上复现。
- 服务器产品和版本，以及连接使用的 TLS 模式。
- 能复现问题的最小步骤、预期与实际结果；SQL 和数据先脱敏。
- `ArkDbError.kind`、可公开的错误码/SQLSTATE、脱敏日志；发生在连接、查询、取消还是清理阶段。

文档问题请同时给出页面链接。不要提交密码、私钥、认证材料、客户数据或未经检查的服务器错误原文。
